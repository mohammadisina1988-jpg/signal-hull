# Review and reproducibility boundaries

The report source is fixed at deployment by repository, commit-pinned HTTPS URL and raw SHA-256. The contract checks the fetched bytes, exact ordered source schema and complete clauses. It does not authenticate an organization, prove commit ancestry or certify that a physical sensor produced the observations. The synthetic fixtures deliberately include superseded drafts, zero observations and pooled counts whose individual split is unresolved.

The leader and every validator fetch independently. Validators independently extract all ten values and then perform a separate substantive audit against every full clause. A valid hash, plausible row sum, correct JSON shape or matching subset of counts alone is insufficient. Exact cells are compared; no confidence tolerance can cross a decision boundary. UNKNOWN never becomes zero, a default probability or an invented pooled split. Matching model failures are not approved.

Known observations must have twelve trials per context and counts summing to that total. These requirements define the bounded empirical-channel model. Wrong totals produce INVALID_COUNTS; missing knowledge produces REVIEW. Neither status permits design or composition. The channel cannot be replaced by an administrator. A corrected source requires a new deployment.

The exact solver considers all sixteen deterministic signal rules. The geometric boundary retains extreme points and a deterministic representative mask for duplicate responses. An accepted filter has rational probabilities in [0,1], exactly induces its requested response in both contexts and is reconstructed from at most three deterministic rules. A separating witness is independently checked against every deterministic rule and therefore against every convex mixture. The diagonal degenerate case requires no floating point or zero-area division.

Composition stores a prior feasible record index plus two postprocessing probabilities. It computes an affine transformation of the actual parent selector, preserves the exact induced profile and does not resynthesize a different selector with merely the same profile. Unattainable designs cannot become parents. The parent is immutable. Three composition layers and sixteen total records bound source-independent work and denominator growth. Under these bounds, cross-products used by the JavaScript verifier remain safe integers. The contract itself uses exact Python integers.

The registry is permissionless and first-come. Anyone can consume one of the sixteen design/composition slots. It is a bounded reusable construction instance, not a spam-resistant global service. Consumers should validate the fixed source and resulting probabilities for their use. No code samples signals or supplies secure randomness: a client or other contract must provide a suitable sampler if it executes the rule.

There are no native-value transfers, token approvals or arbitrary contract/RPC calls. CLI proof callers use disposable encrypted keystores with no funded assets. Hash journaling prevents automatic replay of ambiguous writes; read retries are bounded. Full receipt vote maps retain dissent and idle entries. FINALIZED and successful execution are distinct checks. Expected failures must preserve the whole state and match exact rejection bytes.

Unit tests mock external sources and models. Independent Python and JavaScript oracles solve cube-slice linear feasibility rather than reproducing polygon construction. Actual VM output is checked across all 169 integer profiles for each complete fixture. Live workflows exercise real fetching/model consensus and freshly verify signed calldata, code bytes, full report/assessment/geometry/design state and 27 preview results across the three ready channels. Any later summary of those checks retains their original verification times rather than pretending an artifact merge is a new RPC check.
